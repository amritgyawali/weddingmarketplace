# The Vivah handbook

This handbook explains how Vivah works, why it is built the way it is, and the rules every change must follow. It is written so that someone who has never seen the project (a developer joining in five years, or an AI coding agent starting a fresh session) can read it and work safely.

> **Last full review:** 2 October 2026 (`main` at PR #20). The weekly documentation pass updates this line. See [17-documentation-maintenance.md](17-documentation-maintenance.md).

## How the documentation is organised

| Layer | Where | Written by | Answers |
|---|---|---|---|
| Rules for AI agents (canonical) | [`AGENTS.md`](../../AGENTS.md) | people, kept current with every change | "What must I never break?" The short, binding version. `CLAUDE.md` imports it. |
| **Handbook** (this folder) | `docs/handbook/` | people | "How does this part work, why, and how do I change it safely?" |
| **Code reference** | [`docs/reference/`](../reference/README.md) | generated by `npm run docs:generate` | "What exactly is exported, with which signature, from which file and line?" |
| Strategy | [`docs/MASTER_PLAN.md`](../MASTER_PLAN.md) | people | Personas, the free production stack, phases P0–P8, owner decisions. |
| Runbooks | [`docs/SETUP_SUPABASE.md`](../SETUP_SUPABASE.md), [`docs/LAUNCH.md`](../LAUNCH.md) | people | Step-by-step: staging backend, then going live. |
| Test status | [`TEST_REPORT.md`](../../TEST_REPORT.md) | people | Last full test run and open defects. |
| AI index | [`llms.txt`](../../llms.txt) | people | A short map an AI tool can load first. |

**If two documents disagree, `AGENTS.md` wins**, then the code, then this handbook. Fix the one that is wrong in the same pull request.

## Reading order

**New developer, first day (about two hours):**

1. [00-rules-and-regulations.md](00-rules-and-regulations.md): the rules. Read all of it.
2. [01-product-and-domain.md](01-product-and-domain.md): what the product does and the words it uses.
3. [02-architecture.md](02-architecture.md): how the pieces fit.
4. The guide for the area you will touch (table below).
5. [15-git-and-collaboration.md](15-git-and-collaboration.md) before your first commit.
6. Run the app with a demo account for each role ([01 §5](01-product-and-domain.md#5-demo-accounts)).

**AI agent, every session:** `AGENTS.md` → [16-ai-agents-guide.md](16-ai-agents-guide.md) → the guide for the area → `docs/reference/index.json` for exact names.

**Designer or product person:** [01](01-product-and-domain.md) → [04-ui-ux.md](04-ui-ux.md) → [09-personas-and-access.md](09-personas-and-access.md).

## Conventions used in these guides

- **MUST / MUST NOT** are binding rules. **SHOULD** is the default; break it only with a reason written in the pull request.
- Rule ids such as `R-FE-3` point to [00-rules-and-regulations.md](00-rules-and-regulations.md). Quote them in reviews and commit messages.
- Paths are relative to the repository root (`wedding-app/` on the owner's machine).
- Every code name in backticks exists in the code at the date above. If you find one that doesn't, the docs are stale: fix them.
